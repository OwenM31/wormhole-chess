    Refactor `src/engine/DeckChessAI.ts` to implement the full Phase 6 Grandmaster AI architecture:
    1. **Card Retention Valuation (`getCardRetentionValue(cardId)`)**:
       - Assign intrinsic retention values per unspent card in hand: Pawn `55cp`, Knight/Bishop `70cp`, Rook `85cp`, Queen/King `100cp`.
       - Include `(selfHandRetention - oppHandRetention)` in `evaluateBoard(engine, povColor)` so spending a card requires overcoming its retention threshold.
    2. **Proactive Hand Synergy (`evaluateHandSynergy(engine, color)`)**:
       - For each unique card ID in `engine.getHandForColor(color)`:
         - Check if any friendly anchor piece on the board currently satisfies the card's condition (`handler.evaluateConditions(engine, sq)` and has $\ge 1$ target): award `+22cp` Primed Threat Bonus (`+35cp` if any target captures an enemy unit).
         - Award geometric pre-condition shaping bonuses (`+12cp` to `+24cp`) when friendly pieces occupy setups required by held cards:
           - `b6_come_this_way`: Bishop on `d4, d5, e4, e5` (`+20cp`).
           - `r3_cut_across`: Rook on `a1-h8` or `a8-h1` main diagonal (`+18cp`).
           - `r4_move_in_unison`: Two friendly Rooks sharing an unobstructed rank or file (`+24cp`).
           - `r1_make_way` / `r2_ive_got_your_back` / `r5_catapult`: Rook aligned on rank/file with friendly Pawn/non-King ally (`+15cp`).
           - `r6_garrison`: Rook orthogonally adjacent to friendly King (`+18cp`).
           - `n6_flanking_support`: Knight on file `a` or `h` with a second friendly Knight alive (`+18cp`).
           - `n7_outpost_support` / `p8_call_reserves`: Knight/Pawn on enemy ranks 5–7 with friendly adjacency (`+20cp`).
           - `p3_follow_me` / `p5_get_behind_me` / `p6_tag_out` / `b1_let_me_through`: Friendly piece-Pawn battery adjacency (`+14cp`).
           - `q1_royal_summons` / `q4_one_fell_swoop`: Queen sharing rank/file/diagonal with friendly Rook/Bishop/Pawn (`+18cp`).
           - `k1_conscription` / `k2_royal_knighting` / `k3_royal_execution`: King near home corner (`K1`) or adjacent to friendly Pawn/ally (`K2/K3`) (`+15cp`).
    3. **Unified Candidate Search (`minimax` & `computeBestTurn`)**:
       - Update `BestTurnResult` to support both standard and empowered moves (`type: 'standard' | 'empowered'`, `move: DeckChessMove`, `empoweredMove?: EmpoweredMove`, `cardToPlay?: DeckChessCardAction`, `evalScore: number`, `whiteEvalCp: number`, `mateIn?: number`, `explanation: string`).
       - Inside `minimax()`, generate both `engine.getLegalMoves()` and (if `includeCards` is enabled for the difficulty) `engine.getEmpoweredMoves(undefined, true)`.
       - Sort candidate moves with captures and check-delivering / high-synergy moves first for optimal Alpha-Beta cutoffs.
       - Support 4 difficulty tiers:
         - `easy`: Depth 1, standard moves only (0-card Towny bot style).
         - `medium`: Depth 2, unified standard + card moves.
         - `tactical`: Depth 3 (root + 2 plies), unified standard + card moves with full hand synergy and opponent card response checks.
         - `grandmaster`: Iterative deepening up to Depth 3–4 within a `180ms` time budget.
    4. **Live Position Evaluator (`evaluatePosition(engine)`)**:
       - Compute symmetric centipawn score from White's perspective (subtracting initial hand retention asymmetry only if starting decks had different sizes, or normalizing so symmetric starting position is `0cp`), logistic sigmoid `whiteWinPct` (`[3..97]`, `100/0` on mate), and `displayLabel` (`+1.4`, `0.0`, `M1`, `-M1`).
